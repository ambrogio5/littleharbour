# Free App Store release preparation

Version **1.0.0 (build 4)** is a prepared free-release candidate with reviewable source. A locally signed QA archive can now be built, and both complete campaigns are replayed automatically with earned resources. This does not establish physical-device performance, human campaign pacing, App Store readiness. Physical-device testing is explicitly deferred by the owner. See [graphics/UI polish](RELEASE-POLISH.md) and [hardening evidence](RELEASE-HARDENING.md).

## Before distribution

- Set the owner's final bundle identifier and development team; provision and export using the owner's Apple Developer account. The locally available signing certificate produced a QA archive, but its cached profile excludes the paired iPhone/iPad. Device-specific provisioning previously reported “No Accounts”. On 1 November 2026, Xcode Settings was checked again and now shows the owner’s Apple account and developer teams. Device registration, valid provisioning and installation still need verification; the owner deferred unlocked-device testing until later. The committed release helper never uploads.
- Exercise real iPhones and iPads, including the oldest intended supported hardware, with Instruments: frame pacing, memory/texture pressure, battery, thermals, background interruption, system document pickers, share sheets, migration/recovery, long sessions and app termination. Check Stage Manager, split view, orientation and accessibility text sizes.
- Complete a human progression playthrough through all five chapters using earned resources and both specialist paths. The new automated earned playthrough covers both paths through completed ferry service in the original engine, generated bundle and Apple JavaScriptCore, including residents, furnished homes and sail refits. No human duration/balance claim is made.
- Review the final shipping screenshots and asset provenance. The Mediterranean terrain, individual building states, painted app icon and 24 resource icons are committed with source prompts. Map labels now avoid collisions, site selection focuses the actual building, and moving boats have wakes. Construction uses three shared families and most upgrades add annexes; these are intentional current-art limitations, not 120 independently painted designs. Extreme zoom can expose terrain resolution. Original concept-image matching cannot be certified because the earlier reference image was unavailable.
- Complete VoiceOver, Reduce Motion, contrast, Switch Control and extreme Dynamic Type testing. Add localization as required for the intended storefronts.

## App Store preparation

- Create the App Store Connect record. Product copy, review notes, TestFlight notes and a privacy policy are prepared in `native/release/APP-STORE-METADATA.md` and the bundled `Privacy-policy.txt`. Final screenshots, rating answers, copyright, review contact, territories and a permanent public privacy URL still need owner review. Settings includes offline privacy information and the public repository support link.
- Review the privacy manifest against the shipping binary and any future SDKs. This build uses monotonic uptime to measure active simulation intervals and declares the corresponding required-reason API. It contains no analytics, advertising, tracking or account service. The monotonic-time declaration follows [Apple’s system boot time required reasons](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype). Reconcile App Store privacy answers with the actual signed build.
- Verify current SDK/submission requirements, encryption/export declarations, all artwork/audio rights and applicable commercial terms at submission time. No claim of App Review approval is made here; use the current [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) at release time.
- The owner chose a **free App Store release** on 1 November 2026. Configure the App Store Connect price as Free. No advertising, paid downloads, subscriptions, in-app purchases or paywalls are part of this release. Territories and the final developer-team/app identity remain to be confirmed. Game Center, iCloud and multiplayer are not implemented.
- Preserve the economy version and native wrapper version independently; add explicit migrations before accepting newer versions. Keep the native bundle and art manifest checks required in CI.

## Version 1.0 scope and limitations

The UI exposes the existing game's systems, including advanced actions, through native activity panels. It does not reproduce every browser presentation convenience: persistent pinned goals, three browser target-preset slots, and a named town editor remain absent. Native plain-browser import starts new evolution history because browser evolution lives under a separate storage key. Map position, zoom and the chosen district are remembered locally on the device; they do not travel inside economy exports. There is no automatic synchronization between browser and native saves.

The candidate is English-only and silent. It includes production smoke and boat wakes, but no worker characters, animated mill wheel or authored music. Human campaign pacing and physical-device performance remain unverified. Existing browser play remains on main until the user separately chooses to merge; no deployment changes or automatic merge are part of this work.
