# Free App Store release preparation

Version **1.0.0 (build 14)** is a QA candidate with the approved [long-play economy and investments](LONG-PLAY-ECONOMY.md), reduced bottom spacing, persistent appearance, revised landscape framing, the post-ferry [Harbour Festival](HARBOUR-FESTIVAL.md), and [native story voice and memories](STORY-VOICE.md). Both original campaigns and both festival branches replay with earned resources. QA installation and informal device play do not establish full physical acceptance, human pacing or App Store readiness. No App Store upload or submission has occurred.

## Before distribution

- Confirm the owner's final production identifier and team, then archive/export with distribution credentials. Development signing now installs the isolated Harbour QA identity on the paired iPhones. This does not validate App Store distribution provisioning or the production identity. The committed release helper never uploads.
- Exercise real iPhones and iPads, including the oldest intended supported hardware, with Instruments: frame pacing, memory/texture pressure, battery, thermals, background interruption, system document pickers, share sheets, migration/recovery, long sessions and app termination. Check Stage Manager, split view, orientation and accessibility text sizes.
- Complete a human progression playthrough through the five original chapters and the festival using earned resources, both specialist paths and both festival themes. The new automated earned playthrough covers both paths through completed ferry service in the original engine, generated bundle and Apple JavaScriptCore, including residents, furnished homes and sail refits. No human duration/balance claim is made.
- Review the final shipping screenshots and asset provenance. The Mediterranean terrain, individual building states, painted app icon and 24 resource icons are committed with source prompts. Map labels now avoid collisions, site selection focuses the actual building, and moving boats have wakes. Construction uses three shared families and most upgrades add annexes; these are intentional current-art limitations, not 120 independently painted designs. Extreme zoom can expose terrain resolution. Original concept-image matching cannot be certified because the earlier reference image was unavailable.
- Complete VoiceOver, Reduce Motion, contrast, Switch Control and extreme Dynamic Type testing. Add localization as required for the intended storefronts.

Final screenshots, rating answers, copyright, review contact, territories and a permanent public privacy URL still need owner review. - Review the privacy manifest against the shipping binary and any future SDKs. This build uses monotonic uptime to measure active simulation intervals and declares the corresponding required-reason API. It contains no analytics, advertising, tracking or account service. The monotonic-time declaration follows [Apple’s system boot time required reasons](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype). Reconcile App Store privacy answers with the actual signed build.
- Verify current SDK/submission requirements, encryption/export declarations, all artwork/audio rights and applicable commercial terms at submission time. No claim of App Review approval is made here; use the current [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) at release time.
- The owner chose a **free App Store release** on 1 November 2026. Configure the App Store Connect price as Free. No advertising, paid downloads, subscriptions, in-app purchases or paywalls are part of this release. Territories and the final developer-team/app identity remain to be confirmed. Game Center, iCloud and multiplayer are not implemented.
- Preserve the economy version and native wrapper version independently; add explicit migrations before accepting newer versions. Keep the native bundle and art manifest checks required in CI.

## Version 1.0 scope and limitations

The UI exposes the existing game's systems, including advanced actions, through native activity panels. It does not reproduce every browser presentation convenience: persistent pinned goals, three browser target-preset slots, and a named town editor remain absent. Native plain-browser import starts new evolution history because browser evolution lives under a separate storage key. Map position, zoom and the chosen district are remembered locally on the device; they do not travel inside economy exports. There is no automatic synchronization between browser and native saves.

The candidate is English-only and silent. It includes production smoke and boat wakes, ambient painted townspeople and Elena as a guide. People are cosmetic, not independently simulated workers. There is no animated mill wheel or authored music. Human campaign pacing and physical-device performance remain unverified. Existing browser play remains on main until the user separately chooses to merge; no deployment changes or automatic merge are part of this work.

Build 14 changes the shared town schema to 14. The older deployed browser cannot import it; updated browser sources are tested but are not deployed. Settings exposes the compatibility boundary and conditional older-browser export. Human before/after pacing was deferred by the owner; this candidate is not yet accepted for release.
